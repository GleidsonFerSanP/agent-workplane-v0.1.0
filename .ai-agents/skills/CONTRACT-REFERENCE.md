# Contract Reference & Interface Validation

In `agent-workplane`, deterministic routing across multiple agents (Codex, Claude, Antigravity) relies on strict TypeScript contracts. A mismatch between the decision plane and execution plane causes silent failures or invalid routing.

Use the AI Project Context MCP tools to register, fetch, and validate contracts rather than guessing interface shapes.

---

## 🚨 Critical Path Rule
**All file path parameters MUST be relative paths starting with `./`**:
- ✅ `validate_contract({ file_path: "./src/core/types.ts" })`
- ❌ `validate_contract({ file_path: "/Users/.../src/core/types.ts" })`

---

## 🛠️ Contract MCP Tools

| Tool | Purpose | Example |
|---|---|---|
| `register_contract` | Register a critical interface contract in MCP | `register_contract({ file_path: "./src/core/types.ts", name: "RouteDecision" })` |
| `get_contracts` | Retrieve registered interface definitions | `get_contracts({ file_path: "./src/core/types.ts" })` |
| `validate_contract` | Check if implementation adheres to the registered contract | `validate_contract({ file_path: "./src/executors/base.ts" })` |

## 📋 Core Project Contracts in `./src/core/types.ts`

### 1. `TaskEnvelope`
The immutable input representation created during task intake (`./src/core/intake.ts`):
```typescript
export interface TaskEnvelope {
  id: string; // Stable hash computed from workspace and objective
  objective: string;
  source: { type: "prompt" | "github-issue"; ref?: string };
  workspace: string;
  constraints: string[];
  acceptanceCriteria: string[];
  hints: string[];
  createdAt: string;
}
```

### 2. `TaskClassification`
Generated by Jev decision client (`./src/decision/jev.ts`) or deterministic heuristic fallback (`./src/decision/heuristics.ts`):
```typescript
export interface TaskClassification {
  kind: TaskKind; // "feature" | "bugfix" | "refactor" | "review" | "investigation" | "maintenance" | "unknown"
  complexity: Complexity; // "trivial" | "simple" | "medium" | "hard" | "unknown"
  architectureImpact: number;
  securityRelevance: number;
  visualReasoning: number;
  repoExploration: number;
  testingNeed: number;
  parallelizable: number;
  confidence: number;
  source: "jev" | "heuristic";
}
```

### 3. `RouteDecision`
The output of the Quality-First Router (`./src/routing/router.ts`):
```typescript
export interface RouteDecision {
  primary: ExecutorId;   // "codex" | "claude" | "antigravity"
  reviewer: ExecutorId;  // Independent secondary executor
  scores: RouteScore[];
  fallback: ExecutorId[];
  rationale: string[];
  validationStrength: "normal" | "strong" | "strict";
}
```

### 4. `Executor` Interface (`./src/executors/base.ts`)
Base contract implemented by `CodexExecutor`, `ClaudeExecutor`, and `AntigravityExecutor`:
```typescript
export interface Executor {
  readonly id: ExecutorId;
  execute(task: TaskEnvelope, options?: ExecuteOptions): Promise<ExecutionResult>;
  review(task: TaskEnvelope, diff: string): Promise<ReviewResult>;
}
```

## 🔄 Interface Modification Workflow

When editing types or core signatures:

1. **Inspect Existing Contracts**:
   ```typescript
   get_contracts({ file_path: "./src/core/types.ts" });
   ```
2. **Make Minimal Contiguous Edits**:
   Avoid breaking downstream consumers in `./src/executors/` and `./src/orchestration/`.
3. **Validate Interface Contracts**:
   ```typescript
   validate_contract({ file_path: "./src/core/types.ts" });
   ```
4. **Run Native Typecheck & Tests**:
   ```bash
   npm run check
   npm run test
   ```
